## Summary

In September, the WG published all seven accepted Observability & Traceability terms to the shared AAIF taxonomy, merged the Agent Behavior Trace Model execution plan, published an Agent-to-Tool local CLI boundary analysis, and opened an upstream ARD lifecycle-observability proposal backed by implementation evidence. The State, Context & Reasoning focus group also began recruiting contributors and scoping candidate deliverables around state-space representation and harness-independent state inference.

For the Agent Behavior Trace Model, we changed our approach in September to be more evidence-driven. We analyzed OpenTelemetry support across the major coding agents and agent SDKs and found it highly inconsistent, even among implementations that claim to follow the same GenAI conventions: different span structures, different session identifiers, outdated usage attributes, and no common way to record approvals. Given that landscape, we determined that a change of course, starting from evidence of what agents actually emit, is a better approach than designing a model up front. Rather than build a full reference implementation of a new specification, we are identifying where existing OpenTelemetry instrumentation falls short in real agents, and building to address those shortcomings. We believe we are on track to deliver a first cut of the Gap Analysis and the Trace Model Recommendation. Success for the first cut is a direction the WG agrees to take forward in discussion with our OpenTelemetry partners.

- **Agent Behavior Trace Model.** Merged the execution plan and created eight follow-on issues covering baselines, the shared contract, tests, implementation, independent interpretation, runnable examples, and upstream contributions. As we began the reference implementation, we realized a better path than implementing a full new specification: use Goose, AAIF's own agent, which already has an OpenTelemetry integration, as the reference. We capture what it emits today against the execution plan's four questions (continuity, calls and retries, approvals, effects), record the gaps, and propose extensions to the existing OpenTelemetry integration where the evidence shows a need. The Goose capture setup is built, and the first baseline will be shared with the WG in October. The follow-on issues are being reworked to reflect this evidence-first order.

- **AAIF taxonomy (leads: Joe Maionchi and Pavan)** Merged definitions for Reasoning, Agent Trajectory, Context Propagation, Context Assembly, Memory Access, Retrieval, and Traceability into the shared Taxonomy & Landscape repository. Further proposed terms continue in the Taxonomy & Landscape repository.

- **Cross-boundary observability.** Published the first filled Agent-to-Tool matrix pass using a local CLI realization. The analysis maps OpenTelemetry GenAI and CLI spans, W3C Trace Context and Baggage, process context propagation, lifecycle, outcomes, provenance, security, and timing. The core cross-boundary model, the Agent-to-MCP analysis, and additional runtime/HITL rows remain under review.

- **LLM Primitives & Protocols (leads: Matthew Khouzam and Zayne Turner) - ARD lifecycle observability.** Coming out of the focus group's work, Pavan opened an upstream ARD specification issue proposing non-normative guidance to correlate discovery, federation, trust-evidence verification, resource selection, policy decisions, and native-protocol handoff using W3C Trace Context. The proposal is backed by a Registry and MCP client prototype spanning ARD REST, Registry, Agent Gateway, a policy processor, and the selected MCP server. The experiment identified an external policy-processing boundary that required explicit context forwarding and showed that a rejected resource produced decision evidence without downstream invocation. The guidance remains under discussion and has not been adopted by ARD. Also, began gathering interested contributors and scoping other possible focus-group deliverables.

- **State, Context & Reasoning (lead: Govindaraj).** Began gathering interested contributors and scoping possible focus-group deliverables. Candidate directions include a concrete agent state-space representation; a lightweight state-inference layer for custom harnesses; observable models for tasks, goals, steps, subagents, skills, post-inference behavior, and multi-agent topologies; and an evaluation of whether inferred state improves verification or evaluation quality enough to justify its cost. Deliverable scope, owners, and validation criteria are not yet agreed and are being discussed.

- **Landscape and use cases.** Updated the prior-work survey with A2A as an AAIF-hosted interoperability project and refreshed the prior-work and use-case documents to use organization-neutral language.

- **Scope and coordination.** The WG agreed to include lower-layer observability within the Primitives & Protocol Observability focus area, with Trace leading the provenance effort. The group also reviewed Agent Action Capsule as a possible worked example for verifiable action evidence and approved adding a monthly APAC/APJ synchronization meeting. These are reported meeting outcomes; implementation artifacts have not yet been published.

- **Focus-group structure.** The Orchestration & Coordination track folded into the full WG after further discussion showed overlapping scope; working on the shared problems together was more effective than running them separately. Multi-agent lineage fits better alongside delegation work in the trace model's milestone 2, so it was deferred there. It is tracked, not dropped.

## Risks and Mitigation

- **Undecided approach (main September risk).** In September our approach to the trace model was still largely undecided. After the first cut of work and WG discussions, we have a much clearer path: evidence-driven, starting from what real agents emit today, with Goose as the reference implementation. We will ask the WG to agree the milestone 1 scope, including which of the charter's three dimensions it models, enables, or defers, at the September 30 meeting.
- **September reference implementation.** We did not deliver the two agent examples planned for September. Starting that work is what showed us the evidence-first path above, and the Goose capture setup is now built.
- **Community alignment is the long pole, not spec authorship.** With current tooling, drafting a specification is fast. What takes time is agreeing across the community on which pain points matter and why. We count work as blocked when it is pending alignment with the WG. To reduce that, we are moving more discussion out of synchronous WG meetings into asynchronous channels (the WG's Discord and GitHub), and identifying contributors interested in each area. On the TC's question about automating a spec: evidence captures and shared test cases reduce reviewer load, but don't replace the WG's consensus review.
- **Cross-boundary lead coverage.** This needs more discussion among the chairs; we will raise it again at the next WG chairs meeting.
- **Cross-boundary liaisons.** We are starting with the ARD contact the TC offered (Junjie Bu). The cross-boundary work will need liaisons from across the community, and we are seeking alignment with the other offered contacts (A2A, ADK, Agent Gateway, Cloud Trace) through the WG liaison roster.
- **ARD proposal.** The ARD lifecycle-observability proposal is open, and its adoption depends on community feedback and alignment with upstream specifications.
